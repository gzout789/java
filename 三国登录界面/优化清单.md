## 二、优化清单（按「收益 ÷ 成本」排序）

### P0 · 立即处理（低风险、收益立竿见影）

#### 1. 删除死资源，瘦身构建产物 `[ ]`
- **问题**：`vue/public/heroes/ink/`（22 张水墨 PNG，共 **43MB**）没有任何代码引用；
  `vue/public/heroes/ref.jpg`（1MB）也是孤文件。`public/` 会被原样打包进 `dist/`，
  等于这 44MB 白白进生产包。
- **证据**：全站 `ink` 只出现在 CSS class 名（`ink-ripple-host` / `bg-ink`），与目录无关。
- **做法**：删除 `ink/` 目录与 `ref.jpg`；确认无引用后即可删。
- **验证**：`cd vue && npm run build`，观察 `dist/` 体积是否骤降约 44MB。

#### 2. 硬编码密码外置到环境变量 `[ ]`
- **问题**（三处明文）：
  - `springBootTest/src/main/java/.../config/DemoDataSeeder.java` → 后台账号 `admin / admin123`
  - `springBootTest/src/main/resources/application.properties` → MySQL `root / 123456`
  - 同上文件 → JWT 密钥 `sanguo-login-jwt-secret-key-2026-fenglin-please-change-me`
- **做法**：改为 `${DB_PASSWORD:123456}`、`${JWT_SECRET:...}` 等 Spring 占位符，
  真实值放 `.env` / 环境变量，并把 `.env` 加入 `.gitignore`。
- **风险**：低。改完重启后端自测登录 + 后台登录即可。

---

### P1 · 建议处理（工程化短板）

#### 3. 引入 Git 版本管理 `[ ]`
- **现状**：项目根目录与 `vue/` 均**无 `.git`**。此前修过白屏、弃牌卡死、座位溢出等回归 bug，
  无版本管理意味着无法回滚、无法 diff、无法追溯。
- **做法**：先建 `.gitignore`（务必排除 `node_modules/`、`dist/`、`.env`、`_shots/`、
  `_chrome_profile/`、`*.log` 等），再 `git init` 提交首个基线。

#### 4. 补 ESLint + Prettier + `.gitignore` `[ ]`
- **现状**：约 1 万行前端代码，无任何 lint 约束；未用变量、`console.log` 残留只能靠人肉。
- **做法**：
  - `vue/` 引入 `eslint` + `eslint-plugin-vue` + `prettier`，配 `vue` 推荐规则；
  - 根目录与 `vue/` 各补一份 `.gitignore`。

#### 5. 后端补单元测试 `[ ]`
- **现状**：`springBootTest/src/test` 目录不存在。
- **优先补**（纯逻辑、易测、价值高）：
  - `JwtUtil`：签名 / 校验 / 过期 / 篡改 token 拒绝
  - `UserService`：登录校验、注册重复账号、密码加密
  - `RecruitService`：招募逻辑与边界
- **做法**：引入 `spring-boot-starter-test`，JUnit 5 + Mockito。

---

### P2 · 长期规划（结构优化，成本较高）

#### 6. 拆分超大单文件 `[ ]`
- **现状**（超过 1000 行的文件）：
  - `src/components/SanguoHome.vue` — **2358 行**
  - `src/game/engine.js` — **1476 行**
  - `src/components/admin/AdminApp.vue` — **1460 行**
  - `src/components/game/SanguoGame.vue` — **1386 行**
  - `src/components/SanguoLogin.vue` — **1318 行**
- **做法**：按「视图 / 业务逻辑 / 子组件」拆分，例如把 `SanguoHome` 拆成
  英雄榜、军机要务、烽火快报、总览四个子组件；`engine.js` 按「结算 / 判定 / AI」拆模块。

#### 7. 原图 PNG 进一步瘦身 / 迁移 OSS `[ ]`
- **现状**：26 张原图 PNG 每张约 2MB（合计约 58MB）。列表 / 牌桌已走 `opt/*.webp` 缩略图，
  但原图仅被 `useHeroImg.js` 的 `heroFullImg()` 引用，而该函数**当前零调用**。
- **做法**（三选一）：
  1. 若确无「查看高清原图」需求 → 直接删除 26 张原图，仅留 `opt/`；
  2. 保留则压缩至 500KB 以内（转 webp / 有损压缩）；
  3. 迁到对象存储（OSS/COS）+ CDN，仓库只留缩略图。

#### 8. 登录页大图懒加载 + CDN `[ ]`
- **现状**：若登录页仍直出大体积背景图，首屏加载慢。
- **做法**：`loading="lazy"`、占位图、走 CDN。
