## 二、优化清单（按「收益 ÷ 成本」排序）

### P0 · 立即处理（低风险、收益立竿见影）

#### 1. 删除死资源，瘦身构建产物 `[x]`
- **问题**：`vue/public/heroes/ink/`（22 张水墨 PNG，共 **43MB**）没有任何代码引用；
  `vue/public/heroes/ref.jpg`（1MB）也是孤文件。`public/` 会被原样打包进 `dist/`，
  等于这 44MB 白白进生产包。
- **证据**：全站 `ink` 只出现在 CSS class 名（`ink-ripple-host` / `bg-ink`），与目录无关。
- **做法**：删除 `ink/` 目录与 `ref.jpg`；确认无引用后即可删。
- **验证**：`cd vue && npm run build`，观察 `dist/` 体积是否骤降约 44MB。
- ✅ **完成 2026-11-02**：已删除 `ink/`（22 张 43MB）与 `ref.jpg`（1MB），`grep` 全站确认
  源码零引用（仅 node_modules 的 inkml MIME 类型无关匹配）。保留 26 张原图 + `opt/` 缩略图。

#### 2. 硬编码密码外置到环境变量 `[x]`
- **问题**（三处明文）：
  - `springBootTest/src/main/java/.../config/DemoDataSeeder.java` → 后台账号与初始密码明文写在 `@Value` 默认值
  - `springBootTest/src/main/resources/application.properties` → MySQL `root / 123456`
  - 同上文件 → JWT 密钥 `sanguo-login-jwt-secret-key-2026-fenglin-please-change-me`
- **做法**：改为 `${DB_PASSWORD:123456}`、`${JWT_SECRET:...}` 等 Spring 占位符，
  真实值放 `.env` / 环境变量，并把 `.env` 加入 `.gitignore`。
- **风险**：低。改完重启后端自测登录 + 后台登录即可。
- ✅ **完成 2026-11-02**：三处明文全部外置 —— `application.properties` 改用
  `${DB_USERNAME}`/`${DB_PASSWORD}`/`${JWT_SECRET}`/`${SEED_ADMIN_USERNAME}`/`${SEED_ADMIN_PASSWORD}`/
  `${SEED_DEMO_PASSWORD}`；`DemoDataSeeder` 三处密码改用 `@Value` 注入；新增
  `springBootTest/.env.example` 模板；`启动后端.bat` 启动时自动加载 `.env`（若存在）；
  `.gitignore` 已排除 `.env`。默认值保留，本地零改动即可启动。

### P1 · 建议处理（工程化短板）

- **现状**：项目根目录与 `vue/` 均**无 `.git`**。此前修过白屏、弃牌卡死、座位溢出等回归 bug，

  `package.json` 加 `lint` / `lint:fix` / `format` 脚本。`npm run lint` 当前 **0 error
  9 warning**（均为老代码「未使用变量」类噪音，`no-useless-assignment` 已降为 warning）。

#### 5. 后端补单元测试 `[x]`

### P2 · 长期规划（结构优化，成本较高）

#### 6. 拆分超大单文件 `[1/5]`
- **现状**（超过 1000 行的文件）：
  - `src/components/SanguoHome.vue` — **2358 行**
  - `src/game/engine.js` — **1476 行** ✅ 已拆（2026-11-02）
  - `src/components/admin/AdminApp.vue` — **1460 行**
  - `src/components/game/SanguoGame.vue` — **1386 行**
  - `src/components/SanguoLogin.vue` — **1318 行**
- **做法**：按「视图 / 业务逻辑 / 子组件」拆分，例如把 `SanguoHome` 拆成
  英雄榜、军机要务、烽火快报、总览四个子组件；`engine.js` 按「结算 / 判定 / AI」拆模块。
- ✅ **engine.js 完成 2026-11-02**：1476 → 主文件 329 行，按职责拆出 5 个子模块
  `engine/{combat,damage,deck,distance,skills}.js`，用 `Object.assign(Game.prototype, mixin)`
  合并（方法调用与实例状态不变，纯组织性重构）。冒烟测试 3/3 局通过、build 通过、eslint 0 error。
- ⏳ 剩余 4 个 `.vue` 组件（SanguoHome/AdminApp/SanguoGame/SanguoLogin）**决定保持现状**：
  样式占文件 55-65% 且基于 CSS 变量高度内聚（含主题覆盖 + 响应式），拆分会破坏视觉体系、
  需四尺寸自检却无法自动化，风险收益比不划算。仅 engine.js 这类「纯逻辑、可冒烟验证」的才拆。

#### 7. 原图 PNG 进一步瘦身 / 迁移 OSS `[x]`
- **现状**：26 张原图 PNG 每张约 2MB（合计约 58MB）。列表 / 牌桌已走 `opt/*.webp` 缩略图，
  但原图仅被 `useHeroImg.js` 的 `heroFullImg()` 引用，而该函数**当前零调用**。
- **做法**（三选一）：
  1. 若确无「查看高清原图」需求 → 直接删除 26 张原图，仅留 `opt/`；
  2. 保留则压缩至 500KB 以内（转 webp / 有损压缩）；
  3. 迁到对象存储（OSS/COS）+ CDN，仓库只留缩略图。
- ✅ **完成 2026-11-02**：选方案 2。26 张原图 PNG（56MB）用 Pillow 压缩为 webp（质量 85，
  每张 150-330KB），`heroFullImg()` 改返回 `.webp`，删除原 PNG。`public/heroes` 从
  **58MB → 6.7MB**（-91%），`npm run build` 验证通过。

#### 8. 登录页大图懒加载 + CDN `[x]`
- **现状**：若登录页仍直出大体积背景图，首屏加载慢。
- **做法**：`loading="lazy"`、占位图、走 CDN。
- ✅ **完成 2026-11-02（不适用）**：核查发现登录页 `SanguoLogin.vue` **无任何 `<img>` 或
  大背景图**，背景全部由 CSS 渐变（radial/linear-gradient 绘天空/月/云/雾/花瓣）绘制，
  template 内 0 个 `<img>`，首屏本就不加载图片资源。此项无需处理。
