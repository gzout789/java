## 2. 术语表（写代码 / 写提示词必须用左列 key）

### 2.1 基础牌与计略

| key | 牌名 | 类别 | 说明 |
|---|---|---|---|
| `slash` | **【击】** | basic | 攻击，对方不出【挡】受 1 点创伤 |
| `dodge` | **【挡】** | basic | 抵消一次【击】 |
| `heal` | **【援】** | basic | 回复 1 点体力 |
| `negate` | **【缓策】** | scheme | 抵消一张计略（**结算前全场窗口**） |
| `steal` | **【探囊】** | scheme | 夺距离 1 以内一张牌 |
| `draw2` | **【广纳】** | scheme | 自己摸两张 |
| `duel` | **【惑敌】** | scheme | 对决，轮流出【击】 |
| `trapSlash` | **【困局】** | scheme·延时 | 判定非红桃 → 目标不能用【击】 |
| `trapDraw` | **【断粮】** | scheme·延时 | 判定非红桃 → 目标不能摸牌 |
| `trapBolt` | **【惊雷】** | scheme·延时 | 黑桃 2–9 → 2 点创伤，否则传下家 |

> ⚠️ **禁止使用【斩】/【避】/【疗】或原版三国杀的「杀/闪/桃/无懈可击」**。
> 早期扩展蓝图 v1 曾用【斩/避/疗】，属笔误，已在 v2 全部改为【击/挡/援】。

### 2.2 回合六阶段（顺序固定）

`启策 start → 判定 judge → 征粮 draw → 用兵 play → 收兵 discard → 收阵 end`

- 手牌上限 = 体力；刘备【昭烈】为 `上限 +2`
- 用兵阶段常规限用一张【击】
- 距离 = 座位环形距离 + 军械/技能修正（见 `engine/distance.js`），**不是纯座次**

### 2.3 两个易混淆的响应钩子

| 钩子 | 时机 | 实现 |
|---|---|---|
| **双挡** | 【击】结算时，目标需打出 2 张【挡】 | 吕布 `double_dodge`、关羽红色牌当【击】时 |
| **【缓策】** | 计略**生效前**，全场可打出【缓策】抵消 | `negate` 独立窗口 |

> 两者互不隶属：【缓策】**不能**抵消【击】，也**没有**「连锁/连续抵消」机制。

### 2.4 技能四型

`常策`（锁定技，自动） / `奇谋`（主动，自己回合） / `应策`（响应，条件触发） / `秘计`（一局一次，走 `game.useSecretSkill()`）

### 2.5 身份四型

`lord` 汉主（明置） / `loyal` 忠良 / `rebel` 群雄 / `spy` 隐客

> 注意：身份 `rebel` 的中文名是「群雄」，**与势力名无关**，别和下面的阵营混淆。

## 3. 阵营 key（只有 4 个）

| key | `FACTIONS[key].name` | 色值 |
|---|---|---|
| `han` | 汉室 | `#9c3a2f` |
| `wei` | 曹魏 | `#3a5f7d` |
| `shu` | 蜀汉 | `#a8701a` |
| `wu` | 东吴 | `#2f6b4f` |

**不存在第 5 个 key。** `factionName(key)` / `factionColor(key)` 在 key 未命中时返回
`'群雄'` / `#8a7a5c` —— 这是**兜底显示值**，不是阵营，也不该被写进数据。

### 3.1 「群雄」到底指什么（三处不同含义，别混）

1. `rules.js` 里 `/* ---------------- 群雄 ---------------- */` —— **`HERO_SKILLS` 的注释分组**，
   收纳吕布、貂蝉、华佗、张飞、马超、黄忠、董卓、袁绍、公孙瓒共 9 名，仅便于阅读。
2. `ROLES.rebel.name` —— **身份名「群雄」**。
3. `factionName()` 的兜底返回 —— **无阵营时的显示文字**。

### 3.2 数据库实测（2026-11-11 核对 `DemoDataSeeder.java`）

后台校验限定「阵营四选一」，`HERO_ROWS` 播种时把「群雄组」武将统一标成了 `han`：

```
{"吕布", "飞将", "han", ...}  {"貂蝉", "闭月", "han", ...}
{"华佗", "神医", "han", ...}  {"董卓", "西凉狼", "han", ...}
```

也就是说：**设定集文档写「群雄阵营（3 名）」是错的**；这些武将在库里是 `han`。
这是一处历史数据权衡（四选一放不下群雄），本次**不擅自改数据库**——
改播种会影响 `/api/stats` 的 `byFaction`、点将台"同阵营折扣"和已招募记录，
属于需要单独评审的数据迁移，不在本次术语治理范围内。

> 📌 结论：写新玩法时，**永远用 `han/wei/shu/wu` 四个 key**；
> 想表达"群雄武将"请用 `HERO_SKILLS` 的分组或武将名白名单，不要发明 `qun` key。

## 6. 新玩法接入契约（给《会盟讨董》等模式用）

1. **不新增人设**：复用 `HERO_SKILLS` 的 26 名武将；每个模式只加一张 `mode_effects` 映射表，
   把武将映射到模式层的效果键，**不改 `skill_text` / `desc` / `allusion`**。
2. **牌堆复用**：`buildDeck()` / `shuffle()` / `cardName()` / `CARDS` / `EQUIPS` / `SUITS`
   直接从 `rules.js` 导入；模式专属牌（战功牌、事件牌）另建独立牌堆，别混进基础牌堆。
3. **术语复用**：模式内牌名一律用【击】【挡】【援】【缓策】；模式专属概念另起中文名，
   但**不要占用既有牌名**。
4. **牌类映射**：如需"兵种"概念，用 `TROOP_MAP` 把既有 `key` 映射到兵种标签，
   不改 `CARDS` 结构。
5. **武将数据源**：优先本地 `HERO_SKILLS`（离线可用）；若读 `/api/heroes` 失败须能降级，
   新模式不得因接口不可用而无法开局。
6. **AI 裁判提示词**：所有牌名、阶段名、阵营 key 从本表复制，禁止凭印象写。
